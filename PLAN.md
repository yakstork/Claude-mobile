# План Clawd

Статус: **этап 3 сделан, собрана 0.8: код, тесты логики и ревью готовы; ждёт проверки на телефоне.**
Этапы 1–2 выполнены и проверены на телефоне (0.7.7).

## Итоги уточнения

- **Цель:** надёжность и тесты, новых фич не добавляем.
- **Главные сценарии:** Clawd появляется при каждом входе в Claude и не пропадает, пока Claude на
  экране; исчезает при уходе на рабочий стол, в «Недавние», в другое приложение; печатает, пока
  Claude отвечает.
- **Известный баг (OnePlus CPH2771, Android 16, Clawd 0.6):** после выхода из Claude и возврата
  Clawd не появляется или появляется и сразу пропадает; возвращается, когда начинаешь печатать.
- **Ограничения:** чистая Java, без Gradle и библиотек (значит, и без JUnit); эмулятора нет —
  на устройстве проверяет только владелец, APK отдаётся файлом в чате. Ключ подписи в облаке
  каждый раз новый: APK ставится после удаления старой версии.
- **Готово =** `./build.sh` собирает APK и гоняет тесты, тесты проходят, баг с повторным входом
  не воспроизводится на телефоне, в README описаны сборка и запуск тестов.

## Что есть

- Пять классов (~2500 строк): `ClawdService` (служба, вся логика), `ClawdView` (рисование и
  анимации), `WebFrames` (кадры), `MainActivity` (настройки, «Проверка»), `Prefs`.
- `./build.sh` собирает и подписывает `build/Clawd.apk` — проверено, работает.
- Диагностика: `status` и «Скопировать отчёт» (снимок узлов у поля ввода и список окон).

## Что сломано или хрупко

1. **Повторный вход в Claude (баг выше).** Гипотеза по коду: `ClawdService.tick()` при
   `foreground == рабочий стол` прячет Clawd без срока давности (ветка для «Недавних»). Если
   лаунчер присылает своё событие окна *после* события Claude (анимация открытия) или Claude при
   возврате события не присылает вовсе, `foreground` застревает на лаунчере, пока Claude не
   откроет новое окно — например, подсказки при наборе. Это совпадает с «появился, когда начал
   печатать». Не подтверждено на устройстве: журнала событий нет.
2. **Тестов нет.** Вся логика решений сидит в `ClawdService` вперемешку с Android API и без
   устройства не проверяется.
3. **Диагностика — только снимок момента.** По отчёту не видно, *почему* Clawd спрятался: нет
   истории событий и решений.
4. Мелочи: версия «Clawd 0.6» зашита строкой в отчёте (расходится с манифестом при обновлении);
   `CLAUDE.md` ссылался на несуществующий `PLAN.md` (теперь есть).

## Самые ценные улучшения

1. Починить повторный вход (п. 1) — с тестом, который ловит застрявший `foreground`.
2. Вынести решения «виден / не виден» и «кто на переднем плане» в класс без Android API и
   покрыть тестами.
3. Тесты на распознавание «Claude отвечает» (шаблоны «Стоп», «в очередь», таймер Code) —
   самая частая регрессия при обновлениях Claude.
4. Журнал последних событий и решений в отчёте — чтобы следующий баг разбирался по одному отчёту.
5. Запуск тестов внутри `./build.sh` и раздел в README.

### Этап 3 — фичи 0.8 (по просьбе владельца; каждая — отдельный выключатель в настройках)

## Решения

- 0.8, по ревью: бросок во время ответа не убирает ноутбук (отряхивается только из покоя);
  ходьба не сбивается при перенацеливании за клавиатурой; слегка приподнятый Clawd сразу
  возвращается на рамку; счётчик не считает остановленные ответы и при выключенной реакции на
  «Стоп»; шапка в стиле claude.ai рисуется под телом, чтобы поднятые руки были поверх.
- 0.8, известное: ответ, закончившийся, пока Claude не на экране, в счётчик не попадает; после
  отправки сообщения Clawd один раз косится вниз (длина текста стала 0).
- Тесты без JUnit: правило «без зависимостей» из `CLAUDE.md`.
- Ключ подписи `keystore/clawd.jks` (им подписаны 0.7–0.7.7) закоммичен в публичный репозиторий
  по решению владельца: APK из любой сессии встаёт поверх. Цена — подписать «обновление» Clawd
  может кто угодно; ставить APK только из своей сборки.
- `/grill-me` в сессии не было — уточнение проведено вручную (4 вопроса).
- Устойчивость рамки в `Logic` не выносили: три строки арифметики, тест мало что дал бы.
- Передний план, полученный Claude «по претензии» над рабочим столом, отзывается при потере
  фокуса (находка ревью): лаунчер может прислать событие в начале жеста, а «Недавние» открыть
  позже и молча. Цена — Clawd на время прячется, если в таком состоянии фокус забрало системное
  окно; после настоящего события Claude этого нет.
- 0.7.1: журнал с OnePlus (Android 16) подтвердил гипотезу — лаунчер шлёт событие окна через
  0,3–0,5 с после входа в Claude, а при выходе — на ~0,7 с позже смены окон. В 0.7 это давало
  «показал → спрятал → показал». Теперь событие рабочего стола, пришедшее когда окно Claude
  сверху и в фокусе, передний план не меняет; дальше он держится на фокусе (защита «Недавних»).
- 0.7.2 (без тестов — логика в Android-аниматоре и дереве узлов, без устройства не проверить):
  рамка перемеряется после любого сдвига поля (замер на анимации залипал до следующего
  изменения в Claude); переезд не перезапускается на каждой проверке к той же цели, дальний
  переезд между вкладками — 240 мс вместо 110.
- 0.7.3 — только диагностика: отчёт не снимается с окна на анимации входа/выхода (раньше почти
  всегда перезаписывался на выходе из Claude) и обновляется раз в секунду; в журнале видно,
  какое окно закрыло Claude.
- 0.7.4 — посадка на рамку. По отчёту и скриншотам с устройства: на главной (одна строка) узел
  рамки совпадает с видимой рамкой, а в чате (две строки, вложения) видимая рамка на 8dp шире
  узла сверху и снизу, и области нажатия кнопок выступают за узел вниз. `Logic.framePad` выводит
  скрытый отступ из этого выступа (+2dp запаса), тест — на числах из отчётов. Допущение:
  отступ сверху равен отступу снизу.
- 0.7.5 — поиск рамки вынесен в `Logic.frame`, тесты на четыре раскладки из отчётов. На главной
  с клавиатурой поле (область нажатия 48dp) выступает вверх за один из контейнеров, и подъём по
  предкам обрывался до настоящей рамки — теперь допускается выступ до 8dp.
- 0.7.6 — чат Code с пустым полем (одна строка): узел рамки без обёртки, видимая рамка на 2dp
  шире, кнопки доходят ровно до края узла. Отступ теперь считается и в этом случае (кнопка
  «доходит или выступает»); само поле ввода кнопкой не считается — иначе поднимало бы Clawd над
  полем поиска.
- 0.7.7 — (1) чат Code, пустое поле или одна строка: область нажатия поля (48dp) выше его
  контейнера, и верх рамки брался по полю — Clawd стоял на 14 px выше. Теперь верх рамки — верх
  самого внешнего подходящего предка. (2) Поле поиска в «Проектах»/«Артефактах»: по просьбе
  владельца опущено на видимую рамку константой 4,5dp (узел поля — область нажатия 168 px,
  видимая рамка 136 px; из дерева это не вывести — подгонка по скриншоту).
- Проверка «окно не на анимации» в отчёте смотрит только корень окна; Claude иногда уменьшает
  содержимое внутри окна (жест «назад»), и такой кадр в отчёт попадает. На посадку не влияет.
- **Открыто:** Clawd прячется на 1–4 с при скриншоте/шторке: в журнале «сверху сист null»
  (системное окно без названия во весь экран, в фокусе) и затем «Claude не на экране» без
  закрывшего окна — окно Claude на это время пропадает из списка или отдаёт пустой корень.
  Владельца не беспокоит; чинить только с новыми данными.
- В журнал не пишутся пропущенные события (клавиатура, плавающие окна) — вытесняли бы историю.

## Идеи (вне плана)

- Не прятаться на 1–4 с после скриншота (нужно понять, что за системное окно без названия).
- В отчёте отличать кадр анимации внутри окна Claude (сейчас проверяется только корень окна).
